# 방배정 앱 UI 규칙

데스크톱(macOS/Windows) 운영자 도구. 태블릿·휴대폰 브라우저에서도 열린다(§8). 한 화면에서 수백 개의 방·인원을 훑는 게 목적이라
**정보 밀도 > 여백**, **색으로 상태 구분 > 글자로 설명** 이 원칙이다.

## 1. 색은 `lib/theme.dart` 에서만 온다

- 화면 코드에 `Colors.red` 같은 걸 직접 쓰지 않는다. `AppColors.*` / `RoomStatus.*` 를 쓴다.
- 새 색이 필요하면 먼저 `AppColors` 에 이름을 붙이고 쓴다. 이름이 안 붙는 색은 안 쓴다.

## 2. 방 상태는 4가지뿐이고 색이 곧 상태다

| 상태 | 조건 | 색 |
|---|---|---|
| 공실 | `used == 0` | 흰색 타일 |
| 여유 | `0 < used < capacity` | 옅은 회색 + 초록 "N자리" |
| 만실 | `used == capacity` | 진한 회색 + "만실" |
| 초과 | `used > capacity` | 연한 빨강 + 빨강 "N명 초과" |

- `used` 는 **항상** `store.peakOccupancy(room)` (날짜 겹침 기준 최대 동시 투숙).
  단순 `occupantsOf().length` 를 쓰면 부분 참석자가 있는 방에서 숫자가 틀린다.
- 판정은 `statusOf(used:, capacity:)` 한 함수만 쓴다. 화면마다 조건문을 새로 쓰지 않는다.
- 색만 믿지 않는다. 타일에는 항상 상태 글자(`statusText`)와 `used/capacity` 숫자를 같이 적는다(색각 이상 대비).

## 3. 방은 `RoomBoard` 로 그린다

`lib/widgets/room_board.dart` 의 `RoomBoard` 하나만 쓴다. 방배정 화면과 현황 화면이
서로 다르게 보이면 안 된다.

- 층별로 묶고 **높은 층이 위** (엘리베이터 층 표시와 같은 순서).
- 층 안은 `boardColumns`(10)칸 격자다. **칸 수는 창 폭에 따라 줄이지 않는다** — 방 자리(`Room.slot`)가
  이 폭을 기준으로 저장돼 있어서, 칸 수를 줄이면 운영자가 맞춰둔 건물 배치가 통째로 어긋난다.
  폭이 모자라면 타일을 `_minTile` 까지 줄이고, 그래도 모자라면 보드를 가로로 굴린다.
- 방이 없는 칸은 빈 자리로 남긴다. 복도·엘리베이터·계단 자리라서 지우면 안 된다.
- 자리 배치는 `layoutSlots(rooms, cols)` 한 함수가 정한다. 화면에서 따로 정렬하지 않는다.
- 자리 옮기기(드래그)는 `RoomBoard(editingLayout: true, onMove: ...)` 로 켠다. 옮기는 건
  `store.moveRoom(room, slot, cols: boardColumns)` — 같은 층 안에서만, 겹치면 서로 바꾼다.
- 보드는 흰 카드. 한 층 = [왼쪽 층 번호 칸 | 방 격자] 한 줄, 층 사이는 선. 층 숫자는 크게(엘리베이터 표시처럼).
- 건물이 있으면 그 건물 첫 층 위에 건물 이름을 보드 폭 한 줄(15px 굵게)로 적는다. 층 칸(60px)에 넣거나
  글자를 줄여 맞추지 않는다 — "반석관 - 예배실" 같은 긴 이름이 안 읽힌다.
- 보드 위에는 `RoomLegend` 를 같이 둔다.

## 4. 여백·모서리·타이포

- 여백 단위는 4의 배수. 카드 안쪽 12~16, 위젯 사이 8, 섹션 사이 20~24.
- 모서리: 타일·버튼·입력 10, 카드/보드 16, 다이얼로그 20. 칩은 알약 모양.
- 톤: 회색 바탕(`AppColors.bg`) 위에 테두리 없는 둥근 흰 카드. 주 버튼·선택·포커스는 파랑(`brand`) 하나.
  선택된 칩·세그먼트는 먹색 바탕 + 흰 글자 — 칩 글자색은 반드시 `WidgetStateColor` 로 상태별로 준다.
- 메뉴는 왼쪽 목록(준비 / 배정 / 스탭 묶음, 폭 148). 사용자가 위쪽 탭보다 이쪽을 골랐다. 데스크톱 기준이고, 좁은 창은 §8.
  메뉴가 폭을 먹으므로 보드 여백(간격 6·층 칸 60·안쪽 16)과 방배정 왼쪽 카드(320)는 1440px 창에서 타일이 `_minTile` 이상 나오게 맞춰 둔 값이다.
- 방 관리도 `RoomBoard` 를 그대로 쓴다(누르면 수정 창). 방 목록을 따로 그리지 않는다.
- 한글 자간은 테마에서 -0.2 로 조여 둔다(M3 기본값은 라틴 기준이라 헐겁다). 제목은 -0.3~-0.8.
- 그림자 대신 1px 테두리(`AppColors.border`)로 면을 나눈다. `elevation` 은 0.
- 숫자(호수, 인원)는 `FontWeight.w700` 이상. 라벨은 12px `AppColors.textMuted`.

## 5. 화면 구조

- 좌: 조건/필터 패널(고정 폭) · 우: 결과 보드 — 방배정·자동배정 두 화면이 같은 골격. 본문 폭이 `splitPaneFrom`(1100) 미만이면 두 단계로 나눈다(§8).
- 액션 버튼은 `Row + Spacer` 대신 `Wrap` 에 넣는다. 창이 좁아지면 그대로 넘친다(RenderFlex overflow).
- `Material` 에 `shape` 와 `borderRadius` 를 동시에 주면 런타임 assert 로 죽는다. `shape` 만 쓴다.

## 6. 기존 화면 점검 체크리스트

기존 화면을 다듬을 때는 **훑기 → 진단(아래 목록) → 고치기** 순서로 한다. 새로 짜지 말고 있는 걸 고친다.
한 번에 조금씩, 고칠 때마다 7번을 돌린다.

- **숫자 폭 고정**: 호수·인원·통계 숫자에 `fontFeatures: [FontFeature.tabularFigures()]`. 값이 바뀌어도 열이 흔들리지 않는다.
- **굵기 위계**: 400/700만 쓰지 않는다. 보조 제목·버튼은 w600, 강조 라벨은 w500. (숫자 w700+ 규칙은 그대로)
- **강조색은 `AppColors.brand` 하나.** `danger/warn/ok/info`·`RoomStatus` 색은 의미가 있을 때만 쓴다. 회색도 `AppColors` 계열 하나로.
- **나란히 놓인 카드·패널**: 제목·숫자·버튼의 높이를 맞춘다. 내용 길이가 달라도 버튼은 아래 한 줄로 정렬한다.
- **상태를 빠뜨리지 않는다**
  - hover·눌림: 직접 만든 `GestureDetector` 위젯은 `InkWell` 로 바꾸거나 `MouseRegion(cursor: SystemMouseCursors.click)` 을 붙인다.
  - 포커스: 데스크톱 앱이라 키보드로 이동했을 때 포커스가 보여야 한다.
  - 빈 상태: 방·참석자가 0일 때 빈 화면 대신 안내 문구와 다음 행동 버튼(예: "참석자 불러오기")을 둔다.
  - 오류: 입력 옆에 인라인으로 표시한다. 다이얼로그로 띄우지 않는다.
  - 지금 누를 수 없는 버튼은 숨기지 말고 `onPressed: null` 로 비활성화한다.
- **다이얼로그 남발 금지**: 간단한 수정은 인라인 편집이나 좌측 패널에서 한다. 다이얼로그는 삭제 확인처럼 되돌릴 수 없는 동작에만 쓴다.
- **문구**: 느낌표·"앗!" 없이 무엇이 안 됐는지 바로 말한다. "저장하지 못했습니다. 다시 시도하세요."
- **아이콘**: Material `Icons.*` 한 벌만 쓰고, outlined·filled 스타일을 한 화면 안에서 섞지 않는다.
- **빠지기 쉬운 것**: 모든 흐름에 되돌아가는 길을 둔다. 정원·날짜 같은 입력은 저장 전에 검증한다.
- **코드**: 주석으로 막아둔 죽은 코드는 지운다. 새 패키지를 쓰기 전에 `pubspec.yaml` 에 이미 있는 게 없는지 먼저 본다.

- **폰트**: Pretendard 한 벌(`assets/fonts`, 400/500/600/700). 테마(`appFont`)에서만 지정한다.
  테마의 컴포넌트 스타일(앱바 제목·버튼·툴팁 등)은 textTheme 과 합쳐지지 않으므로 새로 넣는 TextStyle 에도 `fontFamily: appFont` 를 붙인다.
  700 보다 굵은 굵기는 파일이 없다 — w800/w900 을 쓰지 않는다.

가져오지 않은 것: 여백 늘리기, 비대칭 레이아웃, 모션, 노이즈·글래스 효과, 그림자.
운영자 도구는 밀도가 우선이라 위 1~4번 원칙과 부딪힌다.

## 7. 고치고 나서

`flutter analyze && flutter test` 를 돌린다. `test/widget_test.dart` 가 실제로 pump 해서
위 5번 같은 런타임 assert 를 잡아준다. 위젯을 옮기면 이 테스트의 import 부터 확인한다.

## 8. 반응형 (태블릿·휴대폰)

기획: `PLAN_RESPONSIVE.md`. 기준은 `lib/responsive.dart` 한 곳에만 둔다.

- **크기 3단계**: `windowSizeOf(context)` → compact(< 600, 휴대폰) / medium(600~1199, 태블릿) / expanded(≥ 1200, 데스크톱).
  화면에서 `MediaQuery` 폭을 숫자로 직접 비교하지 않는다. 데스크톱(expanded) 화면은 바꾸지 않는 게 원칙.
- **셸**: expanded = 메뉴 148 / medium = 아이콘 레일 64(툴팁) / compact = 햄버거 + Drawer, 앱바 제목은 지금 탭 이름.
  휴대폰 메뉴는 **Drawer 를 유지한다. 하단 탭바(NavigationBar)로 바꾸지 않는다** — 실기기로 보고 사용자가 정했다.
- **나뉜 화면**: [패널 | 보드] 는 화면이 받은 폭(`LayoutBuilder`)이 `splitPaneFrom` 미만이면 두 단계로(방배정: 인원 → 방, 자동배정: 규칙 → 미리보기).
  두 단계에서는 끌어다 놓기를 끄고 눌러서 고르기만 둔다.
- **보드**: 칸 수 10 은 그대로(§3). 휴대폰은 `RoomBoard` 가 [목록 | 격자] 세그먼트를 스스로 붙이고, 목록 보기는 아무것도 저장하지 않는다.
  휴대폰에서 [자리 옮기기]는 숨기지 않고 끈다(`onSelected: null` + 툴팁).
- **표**: 태블릿은 가로 스크롤, 휴대폰은 두 줄 카드. 상세 창은 데스크톱 옆 400 / 태블릿 오른쪽 겹침 / 휴대폰 전체(`PopScope` 로 뒤로 가기 = 닫기).
- **툴바**: 휴대폰은 [검색 한 줄] + [칩 가로 스크롤] + [주 버튼 하나 | ⋮ 더보기].
- **넓은 다이얼로그**(표·미리보기, 폭 600 이상): `AlertDialog` 대신 `WideDialog` — 휴대폰에서 전체 화면으로 열린다.
- **가로로 긴 표**: 행 이름 칸은 왼쪽에 고정하고 나머지만 가로로 민다(홈스테이 표 `_HomestayChart` 참고).
- **넘치는 Row**: 고정 폭 카드 여러 장을 `Row`+`Expanded` 로 나란히 둔 곳은 휴대폰에서 세로로 쌓거나 가로로 굴린다.
- **밀도**: 터치 기기(`isTouchDevice`)만 `VisualDensity.standard` + 터치 영역 48. 창 폭으로 정하지 않는다(좁힌 데스크톱 창은 마우스).
  휴대폰 다이얼로그 바깥 여백은 16. 둘 다 `MaterialApp.builder` 의 `adaptTheme` 이 한다.
- **검사**: `test/responsive_test.dart` 가 모든 탭을 390 / 820 / 1440 폭으로 그려 overflow 를 잡는다. 새 화면·탭을 만들면 여기서 같이 돈다.
